# Changes completed on 2026-08-18

This document records the Docking Universal 0.5.0 development set completed and validated on 2026-08-18. The defining release change is the ability to package a previously determined, control-approved target protocol and apply it unchanged to new sets of compounds. Production behavior is data-driven for the selected proteins, ligands, pockets, protocols, dates, scores, and software versions. The named public structures remain validation fixtures rather than hard-coded runtime behavior.

## Installation and installed validation

- Added PDBFixer 1.11 to the reproducible Conda environment; Conda resolves its OpenMM dependency. Documented both fresh-environment creation and updating an existing environment before `make install-conda`.
- Added `make install-conda`, which installs `docking-universal` into the active Conda environment and makes the command available on `PATH` from any directory.
- Added `install-conda` to `.PHONY` and retained prefix-based installation.
- Made installed Python and shell entry points resolve their package-local helpers rather than assuming a source checkout.
- Corrected installed receptor preparation to resolve the package-local PDBFixer helper beside the installed preparation command.
- Packaged the small scientific fixtures needed by installed integration validation.
- Made installed validation write under `validation_runs/` in the invocation directory instead of the read-only installation.
- Kept developer unit tests source-tree-only while giving installed copies self-contained quick and integration checks.

## Interactive preparation and docking

- Added a strict-Meeko-first receptor pipeline with conservative PDBFixer repair only after rejection, followed by one documented Meeko batch-cleanup fallback if needed.
- Limited automatic PDBFixer changes to alternate-location resolution, recognized nonstandard-residue mappings, and missing side-chain heavy atoms; missing loops and terminal atoms are reported rather than built.
- Retained `pdbfixer_audit.json` and backend logs so every repair and fallback can be reviewed.
- Added guided handling for Meeko's otherwise unresolved histidine-tautomer ambiguity. The interaction identifies the residue, explains HIE/HID/HIP, permits applying the reviewed state to that residue or all unresolved histidines, and records every assignment in `histidine_template_selection.tsv`; unattended runs must supply an explicit assignment and never guess.
- Added concise failure explanations for unsupported non-standard residues, cofactors, linked glycans/covalent fragments, alternate-location/polymer conflicts, incomplete residues, and histidine ambiguity. Each terminal preparation stop retains a plain-language `receptor_failure_diagnosis.txt` with the likely category, scientific reason, and next review step.
- Clarified that approved screening requires a passing bound-ligand control and exploratory docking requires receptor/site preparation.
- Added guided choices to run a control, continue explicitly as exploratory, or stop when no approved protocol is available.
- Made terminal prompts explain every Finder selection before Finder opens.
- Expanded interactive low-level docking selection for the prepared receptor PDBQT, prepared ligand PDBQT file or directory, and Vina configuration file defining the docking box.
- Kept SDF cleaning, state/conformer generation, and PDBQT conversion in the preparation workflow rather than passing SDF directly to Vina.
- Preserved exact-path choices for Linux, remote shells, and automation.

## Portable approved protocols

- Added the `.duprotocol` portable ZIP format for restarting an approved target-matched screen without the original control directory.
- Made the previously determined receptor preparation, selected pocket/docking box, ligand-ensemble policy, exhaustiveness, seeds, requested pose count, and energy range reusable without alteration for new sets of compounds after the target-matched control passes.
- Carried a concise synopsis of the reused protocol and its validation into later compound-set reports: control status/date, control ligand, recovered-pose RMSD and threshold, locked pocket/box, and software-version comparison.
- Bundles contain the approved `protocol.json`, locked receptor PDBQT, locked docking-box configuration, experimental control SDF, selected control figures/evidence, and a SHA-256 manifest.
- Added safe extraction with path-traversal rejection and verification of every retained file hash.
- Made guided and low-level screening accept `.duprotocol` and legacy `protocol.json`.
- Made locked receptor and box paths relocatable within a bundle.
- Added descriptive bundle naming from target, control ligand, and timestamp after a passing high-level control.
- Recorded protocol creation time, receptor-preparation path, plus Docking Universal, Python, RDKit, MolScrub, Meeko, PDBFixer, and AutoDock Vina versions.

## Reports

- Reorganized control-backed reports into configured protocol, experimental control redocking, and new-ligand docking sections.
- Kept the target/new-ligand label only on the new-ligand results page.
- Reduced default reused-control material to PASS/REVIEW, control date, ligand, best-sampled RMSD, threshold, locked pocket/box, and one combined control overlay.
- Retained detailed control interaction figures and provenance in `.duprotocol`; `--include-control-appendix` produces an expanded audit report.
- Made no-ligand reports contain cavity evidence only: selected fpocket cavity, druggability score, candidate ranking, 3D pocket context, and docking-box geometry.
- Kept completed new-ligand results focused on score/cluster panels, three energy-ranked 3D snapshots, SDF-aware PLIP interaction diagrams, and ranked clusters.
- Added an always-present control-to-new-run software comparison table for control-backed screens. It compares Docking Universal, Python, RDKit, MolScrub, Meeko, PDBFixer, and AutoDock Vina and reports `SAME`, `DIFFERENT`, or `NOT VERIFIED` for every component.
- Made every generated PDF and its JSON provenance state the receptor-preparation path actually observed, without implying PDBFixer changed receptors that passed strict Meeko directly.
- Added a concise PDBFixer change summary to reports where repair was attempted; reports also distinguish changes accepted into the final receptor from a repaired intermediate later rejected by strict Meeko. Detailed changes remain in the retained JSON audit and documentation rather than expanding the PDF.
- Corrected provenance so the new-run table uses versions actually active for the new run rather than repeating control versions.
- Removed redundant version rows to keep the standard complete report to five pages.
- Corrected compound naming so `_pubchem` and `_pubchem_<CID>` filename provenance is not presented as part of the chemical name.
- Added protocol timestamps and portable protocol descriptions instead of temporary extraction paths.

## Validation and tests

In the additional cohort, 12 passed strict Meeko, 19 passed conservative PDBFixer repair followed by strict Meeko, 5 passed the documented final cleanup, and 1 passed after guided histidine-template selection. The remaining three stopped rather than silently resolving a heme/cofactor template, protein-DNA template conflicts, or linked glycans.
- Confirmed that the histidine-limited 5NBX case prepares successfully through the guided choice and retains all 12 selected chain/residue assignments. The result is counted in the 47/50 pipeline total while remaining explicitly distinguished from the 46/50 unattended baseline.
- The expanded installed-copy test exposed and corrected package-local PDBFixer helper resolution before the 40-structure cohort was rerun from clean output directories.
- Confirmed that existing 1HVR and 2R8N examples retain identical prepared receptor PDBQT files under the strict-first pipeline and produce matching selected boxes and docking results.
- Expanded CLI tests for interactive routing, approved-protocol recovery, portable bundle selection, Finder prompts, and installed paths.
- Added unit coverage for bundle use, report discovery, cavity descriptors, PubChem filename cleanup, and matching/mismatching software comparisons.
- Fixed validation fixtures for approved-protocol planning and reporting.
- Passed complete macOS arm64 release validation: installed-tool discovery, real conformer generation, Meeko preparation, ligand-centered and fpocket preparation, Vina smoke docking, control evaluation, approved screen, exploratory screen, clustering, PLIP, PyMOL, and PDF reporting.
- Passed installed integration validation launched outside the repository from the active `docking-universal` Conda environment.
- Made Linux CI exercise the mocked Finder workflow and the real pinned RDKit screening path; the final GitHub Actions run passed.

## Compatibility and scientific scope

- Existing `protocol.json` files remain supported.
- `.duprotocol` is for continuing an approved protocol with additional compounds; it does not replace the complete original control archive.
- Hash and version checks establish input and software consistency. They do not convert retrospective pose recovery into evidence of prospective affinity, pose accuracy, or biological activity.
