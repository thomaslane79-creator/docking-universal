## What is being tested

The original [Mac trial](autodock-gpu-mac-trial.md) found different results from
the same explicit seed. These diagnostics distinguish seed parsing, host
initialization, initial GPU scoring, genetic search, local minimization,
early stopping, compiler arithmetic options, work-group size and tracing
effects. Searches are sequential and guarded against active GUI calculations.

All arms reuse the exact retained ligand/receptor inputs and existing AD4 maps.
The official executable is SHA-256
`8787489e84f0e6f602cc50b5dfaab19c63744a90400521f8f31cf4d800cd8519`.
Builds use Apple clang 17.0.0 (`clang-1700.6.4.2`), native ARM64, OpenCL,
`DEVICE=GPU`, `OVERLAP=OFF`, release `-O3`. Unless explicitly varied, the
kernel flag remains `-cl-mad-enable` and the work-group size is 128.

Short searches fix generation ceilings at 1, 5 or 20, disable heuristics and
outer convergence autostop, and retain population 150. They compare no local
search, ADADELTA and Solis–Wets, with one or twenty LGA runs. Each condition
is invoked three times with the same seed. Separate seed controls compare
`41001`, `41001,0,0` and `41002`.

Full fixed-budget searches compare three repeats per ligand, twenty LGA runs
each, ADADELTA with at most 300 iterations, 42,000 generation ceiling,
autostop/heuristics off: indinavir has an evaluation budget of 5,210,753 and the
flexible screen ligand 12,000,000, **averaged across the twenty LGA runs** by
the engine's stopping test, not a hard individual-run limit. A separate
candidate arm restores the original pilot's
heuristics/autostop settings (`heurmax=12000000`). Repeated seeds are technical
repeats, not independent evidence for pose-recovery rates.

## Located defect and experimental candidate

In `device/calcMergedEneGra.cl`, the intermolecular loop writes each atom's
`gradient_x/y/z` using ordinary, non-atomic `+=`. The following intramolecular
loop adds to the **same** arrays using atomic operations from other work-items.
There is no work-group barrier between these loops. The source comment says
the calculations are independent, which is true for each thread's energy
partial but not for the shared per-atom forces. A delayed ordinary write can
overwrite an atomic force addition. Mixing atomic and non-atomic conflicting
accesses without ordering is a data race under the
[OpenCL memory model](https://registry.khronos.org/OpenCL/specs/unified/html/OpenCL_API.html).

The isolated candidate adds `barrier(CLK_LOCAL_MEM_FENCE)` between these loops,
and corrects that comment. No scoring constants, random generators, search
budgets or minimizer equations are changed. Its only hand-edited source file is
`device/calcMergedEneGra.cl`; `host/inc/stringify.h` is regenerated by the
upstream build to embed the edited kernel. The candidate used for full searches
has **no tracing code**.

An alternative synchronization experiment puts a barrier later, before the
translation accumulators are reused for rotation. That change alone does not
resolve the observed divergence. Removing `-cl-mad-enable` alone also does not
resolve it; native approximate math functions still remain in that diagnostic,
so it must not be described as a full high-precision arithmetic implementation.

Raw checkpoints record initialized host populations and PRNG states, initial
GPU energies, and population/energy/PRNG buffers after genetic and refinement
stages. Population checkpoints include only active genes, not uninitialized
padding. Blocking trace reads can affect scheduling, so uninstrumented
official-release and candidate searches are separate controls. A dedicated
one-local-iteration probe records first gradients before coordinate updates.

## Interpretation boundaries

Identical seeds do not mean identical runtimes. This investigation checks
scientific arrays, coordinates and energies, not timestamps, paths or log
durations. Final-population comparisons include all 150 members per LGA run,
not just the best pose. Short text fingerprints use the engine's printed
precision; raw traced buffers provide bitwise evidence at instrumented stages.

The `REPRO` build macro is not a general cure: in this source its substantive
effect is on the *default*, unseeded host RNG constructor. Both initialization
paths here already use the explicit seed constructor. The parser clears all
three seed fields before reading the supplied seed, so a hidden process-ID
seed is not the explanation.

The one-work-item diagnostic is a different numerical/search configuration,
not an equivalent serial CPU reference. Its later-generation differences mean
one cannot claim that shrinking work-groups alone provides portable determinism,
or that this investigation excludes every additional compiler/kernel issue.

Determinism is not accuracy. The broader population CPU/GPU energy residuals
from the initial trial require separate numerical acceptance; a synchronization
repair alone does not validate those residuals, predict experimental affinity,
or establish equivalence/superiority to Vina. Chemical inventory and independent
3D stereochemistry are checked for every full/default-arm output pose. Crystal
RMSD is symmetry-aware heavy-atom RMSD without ligand fitting in the retained
receptor frame; the screen ligand has no experimental reference.

That remaining energy gate is real: corrected full searches have maximum
winner CPU/GPU total-energy residuals of 0.032 kcal/mol (indinavir) and 0.005
(screen), but other population members with both absolute energies ≤1,000
still reach 12.717 and 8.106 kcal/mol respectively. Corrected default-arm tails
reach 14.930 and 10.348 kcal/mol in the same subset. Do not label these checks
an exhaustive numerical correctness pass. The barrier addresses the demonstrated
128-work-item force race, not every outstanding numerical issue or the separate
one-work-item failure.
