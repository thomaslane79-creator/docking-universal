# Contributing

Contributions that improve portability, diagnostics, or scientific transparency are welcome.

1. Create a focused branch.
2. Keep the workflow compatible with Bash 3.2 unless a version change is discussed first.
3. Run `make test`.
4. Describe the structural case used for validation without committing restricted or sensitive data.
5. Explain any change to pocket eligibility, ranking, centering, or box geometry in `docs/methodology.md`.

Bug reports are most useful when they include the Docking Universal version, operating system, dependency versions, the relevant log excerpt, and a minimal reproducible PDB when it can be shared.
